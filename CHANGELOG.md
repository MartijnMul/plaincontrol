# Changelog

What changes in each release of Plaincontrol. Versions follow [Semantic Versioning](https://semver.org); while the version starts with 0, any release may change how Plaincontrol is installed or configured, and says so.

## Unreleased

- **Install with Homebrew**: `brew install --cask martijnmul/tap/plaincontrol`, and `brew upgrade` keeps Plaincontrol up to date, whether or not you let it update itself.
- **Updates inside the app**: on its second launch, Plaincontrol asks whether to check for updates automatically, once a day; nothing is fetched until you agree. Check for Updates… in the menu checks once, and Settings › General has the same choice. Updates come from the latest GitHub release and are installed only when they carry Plaincontrol's signature. The check sends GitHub nothing but Plaincontrol's version.
- **A settings window**: Settings… in the menu, or Command-comma, shows every setting in three tabs: General (the key to hold, the terminal, the editor, the Claude Code command, the order of a project's actions, and whether the launcher has the Accessibility permission), Projects (projects that are always listed with their names and dev server commands, folders with projects, how long a project stays listed, and zoxide) and Windows (columns for new windows). Each setting says whether it is at its default, with a Reset button where it is not, and Restore Defaults… puts a whole tab back (your projects and folders stay). Changes apply at once, the key to hold included. The settings stay in `~/.config/plaincontrol/settings.yaml`; the window changes only the lines of the setting you change, and keeps your comments and the rest of the file as you wrote it. A file it cannot change in place, such as YAML with anchors, is kept as `settings.yaml.backup` and written anew. While the file cannot be read, the window says why, with a button to open it, and changes nothing. Edit as Text opens the file, and the window follows changes you save there.
- **Settings that complete as you type**: Plaincontrol keeps a description of every setting next to the settings file, as `settings.schema.json`, and a new settings file points at it on its first line. Editors with the YAML language server, such as Zed, or Visual Studio Code with Red Hat's YAML extension, then complete the settings, explain them on hover and flag a mistyped key or value while you type. Nothing is fetched from the internet.
- **Actions in the order you use them**: set `actionOrder` in `settings.yaml` to `selected` and an open project selects the action you use most in it, so Return runs it while the digits stay the same; or to `usage` and the actions you use most in that project come first, their digits moving with them. Use counts as for projects, more for recent use; a project you haven't used an action in yet follows your use in all projects. The default, `fixed`, keeps the same order with the first action selected.
- **Claude Code in the desktop app from the launcher**: with the Claude desktop app installed, a project offers 1, Claude Code Desktop, which starts a new Claude Code session in the project's folder in a window of its own, through the app's File › New Session in New Window and the folder picker in that window, without the app's question whether to trust the folder. With `windows` in the settings, the window takes a free column, as a terminal window does. A folder Claude Code has never worked in opens in the app's main window, after the app asks whether to trust it.
- **Start a project's dev server from the launcher**: a project with a dev server offers Dev server, after the other actions, which starts it in a new terminal window and shows the command it runs. The command comes from the project: `make dev` when its makefile has a `dev` target; or else its `package.json` `dev` script, run with the package manager its `packageManager` field names or its lockfile belongs to (pnpm, Yarn, Bun or npm); or else `make run`; or else `docker compose up --build` when it has a Compose file. Set `devCommand` on a project in `settings.yaml` for any other command, such as one that starts a Python server.
- **An icon of its own**: Plaincontrol has an app icon, four lamps on an enamel panel, and a matching menu bar icon. The menu bar lamps stay unlit until a session waits for you; then one lights up, with the number of sessions waiting beside it.
- **Project launcher**: hold the right Option key on its own, or choose Open Launcher in the menu, for a panel with your projects. Projects with a running Claude Code session come first, those waiting for you marked, then the others by how often and how recently you used them. Type to search every project by name or folder, Backspace to edit the search and Escape to clear it. Up and Down select, Return or Right opens a project and runs the selected action, Left or Escape goes back, and Escape closes. Every row shows a digit that picks it: 1 to 9 open the project in that row, and in an open project 1 runs Claude Code in the Claude desktop app, 2 opens a plain terminal window in the project's folder, 3 opens it in Finder (or in the app you open folders with, such as Path Finder), 4 in your editor and 5 runs Claude Code in a new terminal window there, always in that order, so 4 then 1 starts Claude Code in the fourth project. Without the desktop app or an editor, the actions after it move up a digit. Digits pick rows, so a search can't contain one. While open, the launcher takes the keys before the app in front sees them; a click anywhere closes it. The launcher needs the Accessibility permission, which macOS asks for once.
- **New windows find a free spot**: every screen is split into columns (two on the built-in screen, three on others, a 10-point gap; all can be changed) and a new iTerm2 or Finder window from the launcher takes a free column: on the screen with the pointer first, then on the other external screens, then on the built-in screen. Each screen fills from the columns nearest you, taking you to sit in front of the built-in screen: a screen in front of you from its middle, then from left to right; a screen to your left from right to left, and one to your right from left to right. The editor takes two columns side by side: two thirds of an external screen, or the whole built-in one. When an external screen has enough free columns but not side by side, the windows that fill columns there slide aside to make room, keeping their order and the columns nearest you, before the built-in screen is used; windows that do not fill columns stay where they are. When no columns are free, a window goes on the built-in screen, on the left. Finder and the editor are moved once their new window appears; a window they had open already stays where it is. To let each app place its windows instead, turn off Place new windows in columns in the settings, or set `windows: false`.
- **Your own terminal and editor, without settings**: the launcher opens the terminal you run Claude Code in most, and names its actions after it. Plaincontrol can open iTerm2 windows so far; if you mostly use another terminal, the launcher says so and opens iTerm2. The editor is the one you use most lately, such as Xcode, Cursor or Zed: each time you bring it to the front counts (at most once an hour), and so does a Claude Code session in its terminal. Switch to another editor and the launcher follows within days. Before you have used one, it is the app your Mac opens code files such as JSON, Markdown and Python with, leaving out TextEdit and Xcode, which macOS often sets by itself; or else Visual Studio Code.
- **Launcher settings**: choose the key to hold (right Option, Command, Control or Shift), the terminal and the editor (any app, by name or bundle identifier), and the command that starts Claude Code, in Settings… in the menu.
- **Add a folder from the launcher**: when the list is empty, or a search finds nothing, Return offers Add a folder. Find the folder from the keyboard, starting in your home folder: type to filter, Return, Right or `/` to go into a folder, and Left or Backspace to go up, also through links such as `~/Dropbox`. To add the folder you are in, select the Add row above its folders and press Return; it is selected by itself only in a folder without folders inside. Your home folder and the folders above it cannot be added. The project opens straight away, and stays in the list like any project you use.
- **Projects without listing them**: the launcher lists the folders where you start Claude Code sessions and the projects you open from it, ranked by how often and how recently you used them; nothing to set up. To list folders before you use them, add the folders that hold them under Folders with projects in Settings…: their subfolders are listed while you work on them, by a commit in a git repository, a changed file in any other folder, or a use within `activeDays` (90 by default). Older ones only show up in a search. Subfolders may be links to folders elsewhere; macOS may ask once for access to a synced folder such as Dropbox. Projects listed under `projects`, with an optional name, are always listed.
- **zoxide, when you have it**: if you use [zoxide](https://github.com/ajeetdsouza/zoxide), the launcher also lists the folders you visit most and ranks by both histories. A folder inside a git repository counts for the repository, a folder reached in another case or through a link counts once, and a folder holding several projects, such as the one with all your repositories, is left out. zoxide's data is only read, never changed. Turn it off with `zoxide: false` in the settings.
- **Sessions that crash disappear**: a session also leaves the list, and its notification is removed, when its Claude Code process exits without ending the session, such as after a crash or when it is killed.
- **Jump to a session**: click a session in the menu, or its notification, and its iTerm2 window, tab and pane come to the front, on whichever Space they are. macOS asks once for permission to control iTerm2. Sessions in other terminals, or inside tmux, are listed but cannot be opened yet.
- **Notifications** when a session starts waiting for you (with a sound) or finishes a turn. Each waits 5 seconds and is dropped if the session moves on in the meantime, such as when you answer a permission prompt you were looking at. Each session has at most one notification, removed once the session works again or ends.
- **Session list in the menu bar**: every Claude Code session that reports to Plaincontrol, with its status (working, waiting for a permission, a question, a plan review or other input, or idle), waiting sessions first. The menu bar icon shows how many sessions are waiting for you.
- **Claude Code plugin**: hooks that report each session's status to Plaincontrol over a local socket. Prompts, tool inputs and Claude's replies never leave the hook. The hook command comes with the app, so updating Plaincontrol updates it too; without Plaincontrol installed, the hooks do nothing. Install the plugin from this repository with `/plugin`.
