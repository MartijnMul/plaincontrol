# Changelog

What changes in each release of Plaincontrol. Versions follow [Semantic Versioning](https://semver.org); while the version starts with 0, any release may change how Plaincontrol is installed or configured, and says so.

## Unreleased

- **Project launcher**: hold the right Option key on its own, or choose Open Launcher in the menu, for a panel with your projects. Projects with a running Claude Code session come first, those waiting for you marked, then the others by how often and how recently you used them. Type to search every project by name or folder, Backspace to edit the search and Escape to clear it. Up and Down select, Return or Right opens a project and runs the selected action, Left or Escape goes back, and Escape closes. An open project offers C for Claude Code in a new iTerm2 window in the project's folder, F for Finder and V for VS Code, each also under its own key. While open, the launcher takes the keys before the app in front sees them; a click anywhere closes it. The launcher needs the Accessibility permission, which macOS asks for once.
- **Add a folder from the launcher**: when the list is empty, or a search finds nothing, Return offers Add a folder. Find the folder from the keyboard, starting in your home folder: type to filter, Right or `/` to go into a folder, Left or Backspace to go up, and Return to add it. The project opens straight away, and stays in the list like any project you use.
- **Projects without listing them**: the launcher lists the folders where you start Claude Code sessions and the projects you open from it, ranked by how often and how recently you used them; nothing to set up. To list folders before you use them, name the folders that hold them under `roots` in `~/.config/plaincontrol/projects.yaml` (Edit Projects in the menu creates it): their subfolders are listed while you work on them, by a commit in a git repository, a changed file in any other folder, or a use within `activeDays` (90 by default). Older ones only show up in a search. Subfolders may be links to folders elsewhere; macOS may ask once for access to a synced folder such as Dropbox. Projects listed under `projects`, with an optional name, are always listed.
- **zoxide, when you have it**: if you use [zoxide](https://github.com/ajeetdsouza/zoxide), the launcher also lists the folders you visit most and ranks by both histories. A folder inside a git repository counts for the repository, a folder reached in another case or through a link counts once, and a folder holding several projects, such as the one with all your repositories, is left out. zoxide's data is only read, never changed. Turn it off with `zoxide: false` in the projects file.
- **Sessions that crash disappear**: a session also leaves the list, and its notification is removed, when its Claude Code process exits without ending the session, such as after a crash or when it is killed.
- **Jump to a session**: click a session in the menu, or its notification, and its iTerm2 window, tab and pane come to the front, on whichever Space they are. macOS asks once for permission to control iTerm2. Sessions in other terminals, or inside tmux, are listed but cannot be opened yet.
- **Notifications** when a session starts waiting for you (with a sound) or finishes a turn. Each waits 5 seconds and is dropped if the session moves on in the meantime, such as when you answer a permission prompt you were looking at. Each session has at most one notification, removed once the session works again or ends.
- **Session list in the menu bar**: every Claude Code session that reports to Plaincontrol, with its status (working, waiting for a permission, a question, a plan review or other input, or idle), waiting sessions first. The menu bar icon shows how many sessions are waiting for you.
- **Claude Code plugin**: hooks that report each session's status to Plaincontrol over a local socket. Prompts, tool inputs and Claude's replies never leave the hook.
